title: "Limits"
description: "Every size, count, and rate limit Checkfu enforces."
---

Limits are identical on every deployment. A request over a limit fails with `400`, `409` (for resource storage caps such as memories per store, credentials per vault, and artifact database caps), `413`, or `429`, and the error message names the limit. Lengths are in characters unless marked bytes.

## Request bodies

| Endpoint                                                          | Max bytes             |
| :---------------------------------------------------------------- | :-------------------- |
| Default                                                           | 163,840 (160 KiB)     |
| `POST /v1/agents`, `POST /v1/agents/{agent_id}`                   | 2,837,248             |
| `POST /v1/sessions`                                               | 2,097,152 (2 MiB)     |
| `POST /v1/sessions/{session_id}/events`                           | 802,816 (784 KiB)     |
| `POST /v1/artifacts`, `POST /v1/artifacts/{artifact_id}/versions` | 16,183,296            |
| `POST /v1/files`                                                  | 104,857,600 (100 MiB) |
| Memory create and update                                          | 616,384               |
| MCP `POST /mcp`                                                   | 16,248,832            |

## Lists

| Limit                      | Value                                                           |
| :------------------------- | :-------------------------------------------------------------- |
| `limit`                    | 1 to 100, default 50                                            |
| One page                   | About 4,000,000 bytes. Pages can hold fewer than `limit` items. |
| One Artifact document page | 524,288 bytes of document bodies                                |

## Agents and Environments

| Limit                                   | Value                                                 |
| :-------------------------------------- | :---------------------------------------------------- |
| Agent `name` / `description` / `system` | 256 / 2,048 / 100,000                                 |
| Model ID                                | 256                                                   |
| MCP servers per Agent                   | 20 (name 32, URL 2,048)                               |
| Tool policies per `mcp_toolset`         | 128 (tool name 128)                                   |
| Custom tools per Agent                  | 64 (description 4,096, `input_schema` 16,384 as JSON) |
| Approval deny message                   | 4,096                                                 |
| Environment `name` / `description`      | 256 / 1,024                                           |

Custom tools cannot reuse a built-in name (`read`, `ls`, `find`, `grep`, `write`, `edit`, `delete`, `bash`, `save_artifact`, `artifact_data`, `codemode`, `tool_search`) or start with `mcp__`.

## Rate limits

`/v1` has no request rate limit. Its only `429` responses are the queued-message limit (8) and live Automations capacity (100). Artifact data calls from signed links and public sites are rate-limited:

| Limit                                                        | Value                                   |
| :----------------------------------------------------------- | :-------------------------------------- |
| Per caller network (IPv4 address or IPv6 `/64`) per Artifact | 120 calls per minute                    |
| Per Artifact, all callers                                    | 1,200 reads and 1,200 writes per minute |

Exceeding either rate limit returns `429` with `Retry-After: 60`. Each visitor data call body is also capped at `131,072` bytes (larger bodies return `413`).
